# 用 Linux 查看网络与 IPv4

排查网络问题时，第一步不是急着重装驱动，也不是随手修改配置，而是先看清楚当前状态。

这一页主要学会两件事：

1. 用 `ip a` 找到自己的网络接口和地址
2. 理解 IPv4 地址、网段以及两台设备为什么能直接通信

## 先看本机：`ip a`

在终端执行：

```bash
ip a
```

`ip a` 是 `ip address` 的简写。不同电脑的输出会不一样，但大致结构如下：

```text
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536
    link/loopback 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo

2: enp3s0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500
    link/ether 34:12:98:aa:bb:cc brd ff:ff:ff:ff:ff:ff
    inet 192.168.1.20/24 brd 192.168.1.255 scope global dynamic enp3s0
```

这里不要一口气研究所有字段，先找下面四类信息。

### 1. 接口名

每一段开头类似：

```text
4: enp3s0: ...
```

其中 `enp3s0` 就是接口名。常见名称还有：

- `lo`：回环接口
- `eth0`：较常见的有线接口名
- `enp...`：较新的系统给有线接口使用的可预测名称
- `wlan0`：常见的无线接口名

接口名由系统和硬件决定，**不能照抄教程里的 `enp3s0`**。后续命令需要替换成自己机器中实际存在的那一个。

### 2. 接口状态

尖括号里通常会出现：

```text
<BROADCAST,MULTICAST,UP,LOWER_UP>
```

先关注两个标志：

- `UP`：接口已经启用
- `LOWER_UP`：底层链路通常已经就绪

如果看到：

```text
<NO-CARRIER,BROADCAST,MULTICAST,UP>
```

说明接口本身已经打开，但没有检测到可用的物理链路。网线没插好、对端没有开机或接口选错都可能造成这种情况。

### 3. MAC 地址

类似下面这一行：

```text
link/ether 34:12:98:aa:bb:cc
```

`link/ether` 后面的值就是这块网卡的 MAC 地址。它主要在局域网内部用于把数据交给具体网卡。

初学阶段只需要知道“IP 负责更大范围中的定位，MAC 用于局域网中寻找具体接口”，不需要展开 ARP 报文和交换机学习 MAC 地址的细节。

### 4. IPv4 地址与前缀

以 `inet` 开头的行中包含了 IPv4 地址：

```text
inet 192.168.1.20/24
```

可以把它拆成：

```text
192.168.1.20 / 24
└─────┬─────┘ └┬┘
  IPv4 地址    前缀
```

后面的 `brd 192.168.1.255` 是广播地址，`scope global` 表示这个地址可以在全局网络接口中使用，`dynamic` 通常表示地址来自自动配置。

## `ip a` 中最重要的三个问题

查看任何一台设备时，都可以先问：

```text
1. 我要用的是哪个接口？ 我在实验室，那我可以网线直连，也可以拿实验室wifi做跳板
2. 这个接口是否 UP，并且有 LOWER_UP？ 哈哈骇，判断网线问题的好方法
3. 它有没有合适的 IPv4 地址？ 
```

如果这三步没有确认，后面运行 `ping` 或远程连接时很容易把问题归因到错误的地方。

也可以只看某个接口：

```bash
ip a show dev enp3s0
```

以及查看链路层状态：

```bash
ip link show enp3s0
```

## IPv4 地址

IPv4 地址常见写法是四段十进制数：

```text
192.168.1.20
```

每一段对应 8 个二进制位，因此常见范围是 `0` 到 `255`。计算机内部实际处理的是二进制，点分十进制只是方便人阅读的形式。

初学阶段不需要现场做二进制换算，但要能看懂常见地址的结构。

### 私有地址

下面这些地址通常用于局域网：

```text
10.0.0.0    - 10.255.255.255
172.16.0.0  - 172.31.255.255
192.168.0.0 - 192.168.255.255
```
::: tip
网络的发展不是一蹴而就的，各位可以看“网”文，了解这么多约定是怎么出现的
:::
你可能经常在宿舍、实验室或家用网络中看到 `192.168.x.x`。这些地址一般不能直接出现在公网互联网中，需要经过 NAT 才能访问公网。

### 回环地址

`127.0.0.1` 表示本机自己。
::: tip
诶？那 localhost 是什么
:::

如果程序只在本机运行，经常会使用类似：

```text
127.0.0.1:8080
```

这里的 `8080` 是端口，表示连接到本机某个服务。端口不是这一页的重点，后面配置 NoMachine 或排查服务时会再次遇到。

## 前缀与同一网段

地址后面的 `/24` 叫作前缀长度。

例如：

```text
192.168.1.20/24
192.168.1.30/24
```

可以粗略理解为，`192.168.1` 是它们共同的网段部分，最后的数字用于区分网段中的不同设备。两台设备通常可以直接通过交换机或网线通信。

再看：

```text
192.168.1.20/24
192.168.2.30/24
```

两者通常不在同一个网段，因此需要经过网关和路由器。

::: info 看懂 `/24`
子网掩码是一个当前网络分层体系的实际工具，老教材上的A B C类网络已经是过去时了S
这里不要求掌握复杂子网划分。看到 `/24` 时先建立“前三段相同，通常处在同一个常见局域网”的直觉即可。更小或更大的前缀会改变这个判断。
:::

## 用 `ping` 检查基本通路

`ping` 会向目标发送 ICMP 探测数据：

```bash
ping -c 4 192.168.1.1
```

`-c 4` 表示发送 4 次后停止。Linux 中不写 `-c` 时，`ping` 默认会一直运行，可以用 `Ctrl+C` 停止。

`ping` 的结论要谨慎理解：

- `ping` 通，说明至少有一条路径能够完成基本收发
- `ping` 不通，可能是地址错误、网段不对、目标关机或防火墙拦截(也可能是你网络代理没有进入终端)，或者单纯目标没有开启**ICMP**
- `ping` 通，不代表 SSH、网页或 ROS 节点一定已经启动

## 用 `ip neigh` 看局域网邻居

完成一次局域网通信后，执行：

```bash
ip neigh
```

它通常会显示类似：

```text
192.168.1.1 dev enp3s0 lladdr 11:22:33:44:55:66 REACHABLE
```

这表示当前接口上，目标 IP 已经与某个 MAC 地址建立了邻居关系。

这一页只需要知道：如果局域网设备之间存在通信，`ip neigh` 可以帮助确认 IP 和 MAC 是否已经被系统找到。


如果电脑同时有有线、无线和虚拟网卡，只选择你目前真正联网的那一个。无法确定时，可以结合后一页的 `ip route` 判断默认使用哪个接口。

## 实践 ：一根网线直连两台电脑
先记录你的网络信息   
试试和同学共享网络吧
> 物理连接成功，不等于两台计算机已经能够通过 IP 通信。
> 能互相 ping 通，不代表可以访问互联网哦

### 实验准备

- 两台都有可用网口的电脑
- 一根以太网线
- 两台电脑都方便看到终端
- 不要在正在通过 SSH 使用的网卡上做实验

现代网卡通常支持自动适配线序，普通网线一般可以直连。如果接口一直显示 `NO-CARRIER`，再检查网线、网口和对端设备。

::: warning 先不要随意修改当前联网接口
下面的命令会给网卡添加临时 IPv4 地址。不要对正在承担重要联网任务的接口盲目操作，也不要把命令中的接口名直接复制到自己的电脑上。

实验前先执行 `ip a`，确认接口名；实验结束后删除临时地址并恢复原网络配置。
:::

### 示例地址

这次使用一个尽量避免和常见网络冲突的网段：

```text
电脑 A：192.168.177.1/24
电脑 B：192.168.177.2/24
```

两台电脑处在同一个 `/24` 网段，因此不需要路由器就可以尝试直接通信。

### 第一步：找出直连所用接口

在两台电脑上分别执行：

```bash
ip a
```

假设两台电脑的接口名都是 `enp3s0`，后续命令才可以这样写。实际使用时必须换成自己的接口名。

### 第二步：给电脑 A and B 配置临时地址
> 重启linux不保留
```bash
sudo ip link set enp3s0 up  # 让网卡工作
sudo ip addr add 192.168.177.1/24 dev enp3s0 # 告诉 A 网卡它的地址
sudo ip addr add 192.168.177.2/24 dev enp3s0 # 告诉 B 网卡它的地址
ip a show dev enp3s0 # 检查
```

### 第三步：互相 ping

在电脑 A and B 上：

```bash
ping -c 4 192.168.177.2 # -c 4 : 走 ipv4
ping -c 4 192.168.177.1
```

如果配置正确，双方应该能够收到回复。

### 第四步：查看邻居关系

```bash
ip neigh
```

可以尝试找到 `192.168.177.1` 或 `192.168.177.2` 对应的 MAC 地址。

### 第五步：清理临时地址

实验结束后，在对应电脑上删除地址：

```bash
# 电脑 A
sudo ip addr del 192.168.177.1/24 dev enp3s0

# 电脑 B
sudo ip addr del 192.168.177.2/24 dev enp3s0
```

随后重新连接原来的网络，并用 `ip a` 检查配置是否恢复。

### 如果 ping 不通

按下面的顺序检查：
0. 虚拟机是否是桥接模式，或者确认宿主机下虚拟机的ip
1. `ip a` 中是否看到了正确的接口和地址
2. 接口是否显示 `UP` 和 `LOWER_UP`
3. 双方是否都在 `192.168.177.0/24` 内
4. 防火墙是否允许 ICMP
5. 是否把地址添加到了错误的网卡上

能完成这个实验，就已经理解了“网卡、IP、网段、ping 和邻居关系”之间最基本的一圈关系。
