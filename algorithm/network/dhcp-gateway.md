# 网络自动配置

上一页中，两台电脑是手动填写 IP 地址的。

但现实里的手机、电脑和虚拟机通常接上网络就能使用。它们并不知道自己的地址应该是什么，也不会每次都让人手工输入网关。这个过程主要由 DHCP 完成，而离开当前局域网时，还要依赖默认网关和路由器。

## 一台设备上网前需要知道什么

只拿到一个 IP 地址通常还不够。一个常见的 IPv4 网络配置至少包含：

```text
IP 地址
子网前缀
默认网关
DNS 服务器
```

它们分别回答：

| 配置 | 回答的问题 |
|:-:|:-|
| IP 地址 | 我在这个网络中的地址是什么 |
| 子网前缀 | 哪些目标和我处在同一个局域网 |
| 默认网关 | 目标不在本网段时，先把数据交给谁 |
| DNS 服务器 | 域名应该向谁查询对应的 IP |

手工实验时，我们只添加了 IP 和前缀，所以能够完成同一网段内的直连。但访问互联网还需要找到出口，也就是网关。

## DHCP 是什么

DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）用于自动向设备提供网络配置。

可以把它想成网络中的前台：

```text
新设备：我刚接入网络，应该使用什么地址？
DHCP：你可以使用这个 IP 和前缀，
      同时网关是这里，DNS 服务器是那里。
```

设备获得的配置通常会有一个租期。租期到期前，设备会尝试续租，不需要用户每次手动处理。

这里不展开 DHCP 的详细报文交互，只需要知道：

- DHCP 不只是“发一个 IP”
- 它通常同时告诉设备网关和 DNS 在哪里
- 拔掉网线或切换网络后，地址可能发生变化
- 宿舍、实验室、家庭网络可能有不同的 DHCP 策略

## 为什么大部分个人接触到的网络能够即插即用

把网线插入电脑后，通常会经历下面的过程：

```text
检测到物理连接
  → 启用网络接口
  → 通过 DHCP 请求配置
  → 获得 IP、前缀、网关和 DNS
  → 把结果写入系统网络配置
```

因此在用户看来只是“插上网线就能用”，但系统其实已经完成了一次自动配置。

虚拟机桥接时也是同一个道理。虚拟机进入局域网后，仍然需要从网络中的 DHCP 获得地址，或者由用户手动配置。

::: info 自动配置不代表永远正确
DHCP 配置错了网关、地址池耗尽、网络中存在冲突地址，都会导致看起来“连上了但上不了网”。后面需要用命令确认实际拿到的配置。
:::

## 默认网关

默认网关（default gateway）是本机在不知道目标应该走哪条路时，默认交给的下一台设备。

可以用下面的规则理解：

```text
目标在同一网段  → 直接在局域网中寻找目标
目标不在同一网段 → 先把数据交给默认网关
```

例如：

```text
本机：192.168.1.20/24
目标：192.168.1.30/24
```

两者通常处在同一个局域网，可以直接通信。

如果目标是：

```text
203.0.113.10
```

它显然不在 `192.168.1.0/24` 中，因此需要交给网关继续转发。

## 用 `ip route` 查看路由表

执行：

```bash
ip route
```

输出可能类似：

```text
default via 192.168.1.1 dev enp3s0 proto dhcp metric 100
192.168.1.0/24 dev enp3s0 proto kernel scope link src 192.168.1.20 metric 100
```

先关注两行：

### 默认路由

```text
default via 192.168.1.1 dev enp3s0
```

这表示不知道具体该走哪里时，默认把数据交给 `192.168.1.1`，并通过 `enp3s0` 发出去。

所以在这里：

```text
默认网关：192.168.1.1
出口接口：enp3s0
```

### 本网段路由

```text
192.168.1.0/24 dev enp3s0
```

这表示当前设备连接着 `192.168.1.0/24` 这一个局域网，可以直接从 `enp3s0` 找到同网段目标。

## 查询某个目标会走哪里

除了查看整张路由表，还可以直接询问：

```bash
ip route get 1.1.1.1
```

输出会显示访问这个目标时会使用的出口接口和源地址。若目标需要离开局域网，通常还能看到 `via` 后面的网关。

这个命令很适合确认：

- 系统当前是否选择了正确的网卡
- 访问某个地址时是否会经过预期的网关
- 多张网卡同时存在时，默认路线到底是什么

## 网关和路由器是什么关系

这两个词经常一起出现，但描述的角度不同：

- 默认网关：站在本机角度，表示“默认把数据交给谁”
- 路由器：站在网络角度，负责连接不同网络并决定下一步怎样转发

在家用网络中，默认网关通常就是路由器的内网地址，例如 `192.168.1.1`。

可以把它们理解为：

> 网关是“我这台电脑默认找谁帮忙”，路由器是“那个帮忙继续转发数据的设备”。
> 实际网络拓扑中比较多样，但简单环境默认网关路由器一体

## 交换机与路由器

两者解决的问题不同：

| 设备 | 主要作用 | 数据范围 |
|:-:|:-|:-|
| 交换机 | 连接同一局域网内的多台设备 | 局域网内部 |
| 路由器 | 在不同网络之间转发数据 | 连接多个网络 |

一个简单的局域网可以是：

```text
电脑 A ─┐
电脑 B ─┼─ 交换机 ─ 路由器 ─ Internet
电脑 C ─┘
```

电脑 A、B、C 之间的数据可以经过交换机直接到达。访问 Internet 时，数据则要先交给路由器。

家用路由器通常已经包含一个小交换机，因此背后有几个网口可以直接连接电脑。

## 动手：找到并测试自己的网关

这一节不会修改网络配置，只观察当前环境。

```bash
ip a # 找到接口和地址
# 记录当前联网使用的接口名，例如 `enp3s0`
ip route # 查看默认网关
```

找到类似：

```text
default via 192.168.1.1 dev enp3s0
```

如果系统同时存在多个默认路由，不要急着判断哪个“更正确”。可以先结合 `ip a` 和实际联网接口确认。

### 查询一个公网目标

```bash
ip route get 1.1.1.1
```

观察它选择了哪个接口，以及是否经过默认网关。

### ping 默认网关

假设查到的网关是 `192.168.1.1`，执行：

```bash
ping -c 4 192.168.1.1
```

结果可能有几种情况：

| 现象 | 可能说明 |
|:-|:-|
| 能收到回复 | 本机到局域网网关的基本通路存在 |
| 提示 `Network is unreachable` | 本机可能没有可用的路由或接口未配置 |
| 没有回复 | 网关禁用了 ping、地址错误、防火墙或链路有问题 |

网关不响应 `ping` 不一定代表不能转发数据，但至少需要检查地址、接口和局域网连接。

### (可选)查看 DHCP 配置

Ubuntu 桌面通常使用 NetworkManager。可以执行：

```bash
nmcli device status
nmcli device show enp3s0
```

后者可能需要换成实际接口名。输出中可以看到当前连接、IPv4 地址、网关和 DNS 等配置。

不同 Ubuntu 安装方式的网络管理工具可能不同，因此这条命令只作为观察手段，不是所有系统都必须使用。

## 常见问题

### 有 IP，但没有默认路由

这说明设备可能只在局域网中配置了地址，却不知道怎样访问其他网段。

先检查：

```bash
ip a
ip route
```

如果确实没有 `default via`，需要检查 DHCP 配置、连接配置或是否选择了错误的网络接口。

### 有默认路由，但网关 ping 不通

按顺序检查：

1. 网关地址是否来自当前接口
2. 本机地址和网关是否处在同一网段
3. 网线或 Wi-Fi 是否正常
4. 网关是否禁用了 ICMP
5. 是否存在防火墙或网络隔离

### 地址冲突

两台设备使用了同一个 IP 时，局域网通信可能时好时坏，也可能完全失败。

手工实验结束以后要主动删除临时地址。真实网络中则应由 DHCP 统一分配，避免随意占用地址池。

## 小结

这一页可以压缩成三句话：

```text
DHCP 自动告诉设备：我是谁、网关在哪、DNS 在哪。
ip route 告诉本机：不同目标应该从哪里走。
路由器负责在不同网络之间继续转发。
```

做到这里，我们已经知道了局域网内部的地址，也知道了离开局域网时应该找谁。下一步要解决的是：内网地址怎样访问公网，域名又怎样变成 IP。
